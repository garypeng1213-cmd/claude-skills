# Photo Style Router

把「選風格」和「照風格做」拆成兩步：先判斷，再執行。判斷靠本檔的規則，執行靠上游 skill 原檔。

## 檔案

- `styles.md`：11 張風格卡（A～K），每張寫了素材需求、長相、情緒、適用場景、商用與否、上游入口檔。**每次都要讀。**
- `setup.sh`：把上游倉庫 clone／更新到 `~/.claude/photo-style-vendor/`（下稱 `$V`）。
- 上游原檔只放在 `$V`，不在本倉庫裡（授權原因，見 README.md）。不要把上游內容複製進本資料夾。

## 0. 確認上游已下載

`$V` 不存在或缺少要用的那個倉庫 → 先跑 `bash ~/.claude/skills/photo-style-router/setup.sh`。clone 失敗（例如雲端網路受限）就說明，改用 `styles.md` 的摘要做「近似版」，並明講不是完整上游規則。

## 1. 讀素材，抓五件事

不要一開始就問問題。先從使用者給的東西推斷：

| 要判斷的 | 怎麼看 |
|---|---|
| **素材類型** | 有照片？只有文字？兩者都有？有照片就先看照片內容（主體、場景、光線、色彩、構圖、是否有 EXIF 日期）。 |
| **照片要不要原樣出現** | 「把這張照片做成…」「保留原圖」→ 保留；「照這張的感覺畫…」「當靈感」→ 可以重繪。沒說 → 預設保留。 |
| **情緒** | 安靜／溫柔／克制／強烈／好笑／理性。看文案用字和照片氣氛。 |
| **用途與比例** | 小紅書 3:4、IG 4:5 或 1:1、限動 9:16、公眾號 21:9、影片封面 16:9、書封 9:16。沒說 → 用該風格預設比例。 |
| **商用** | 出現「接案、客戶、商品、廣告、要賣、品牌」→ 視為商用，**排除標 ❌ 的風格**，D 要提醒先讀原授權。 |

只有在「完全沒有素材」時才問使用者要素材。

## 2. 選風格

用下面的決策表縮小範圍，再到 `styles.md` 比對細節。

**只有文字（沒有照片）**

| 想要的感覺 | 首選 | 次選 |
|---|---|---|
| 安靜、留白、金句、文章封面 | A minimal-zine | K mono-color |
| 強烈、有故事、影片／書／專輯封面 | H mondo | I pixel-poster |
| 科技、AI 產品、冷靜復古數位 | I pixel-poster | H mondo |
| 宣言、活動、編輯排版 | K mono-color | A minimal-zine |

**有照片，照片要原樣出現**

| 照片內容／想要的感覺 | 首選 | 次選 |
|---|---|---|
| 家庭、建築、黃昏，要有記憶感、要做成系列 | B photo-relic | C abstract-editorial |
| 構圖漂亮、想要乾淨冷靜的美術館感 | C abstract-editorial | B photo-relic |
| 旅行照、想標日期和地點短句、一地一張 | D travel-abstraction | B photo-relic |
| 風景、植物、街角，想要拼貼手作感 | F gathered-scenes | B photo-relic |
| 飲料、甜點、小物，想要好笑可愛 | J heytea-doodle | E photo-revival |

**有照片，可以重繪（照片只當參考）**

| 想要的感覺 | 首選 | 次選 |
|---|---|---|
| 日記、手帳、溫柔日常 | E photo-revival | A minimal-zine |
| 表達一種情緒、像獨立藝術作品 | G scene-distillation | H mondo |
| 人像特寫、動物，細網點質感 | I pixel-poster | K mono-color |

衝突時的優先順序：商用限制 → 照片要不要保留 → 用途比例 → 情緒。

## 3. 推薦給使用者

給 **2 個**選項（真的只有一個合理時才給 1 個），每個一行理由，寫出「成品大概長怎樣」，例如：

> **推薦 1：B 照片＋版畫記憶** — 你的照片是黃昏的老屋，光線方向清楚，下方可以壓成幾筆深藍墨塊加一點暖橘，很適合做成系列封面。
> **推薦 2：C 照片＋乾淨抽象面板** — 如果你想要更冷、更像美術館目錄，就選這個，標題會是英文襯線字。

用 `AskUserQuestion` 讓使用者選（推薦的放第一個、標 Recommended）。以下情況**不用問，直接做首選**：
- 使用者說「你決定」「直接做」「隨便」
- 使用者已經點名風格

## 4. 執行選定的風格

1. 讀 `styles.md` 該卡寫的上游入口 `SKILL.md`，以及它要求讀的 `references/` 檔。**照上游規則走**——素材判斷、prompt 結構、品質檢查都以上游為準，本檔不覆蓋它的審美規則。
2. 上游寫「用內建生圖工具／image_gen／referenced_image_paths」的地方，一律改成 `codex-imagegen`：
   ```bash
   python3 ~/.claude/skills/codex-imagegen/codex_image.py \
     --out "<輸出資料夾>/<檔名>.png" [--ref "<使用者照片>"] --prompt-file "<prompt.txt>"
   ```
   有照片就用 `--ref` 帶入。比例寫進 prompt，生完必要時用 `sips` 調整。逾時、重試規則照 codex-imagegen 的說明。
3. 上游自帶的 API 腳本（例如 H 的 `generate_mondo*.py`）不要用；上游的本機處理腳本（例如 D 的 `finalize_artwork.py`）照上游指示用，從 `$V` 原位置執行，不要複製出來改。
4. 輸出存到 `~/Desktop/Claude skills/photo-style-router/<日期>-<主題>/`（資料夾不存在就建立），prompt 一併存成 `prompt.txt`。
5. 生完自己看圖，對照上游的品質檢查；明顯不合格就照上游規定重生（通常最多一次）。

## 5. 交付

回覆使用者：
- 成品圖路徑（並用 SendUserFile 送出）
- 用了哪個風格、為什麼（一句話）
- 最終 prompt（上游規定不顯示 prompt 的風格，例如 G，就照上游不顯示，除非使用者要）
- 一個延伸建議：「要不要用第二推薦的風格再出一張比較？」

## 只要 prompt 模式

使用者說「只要 prompt」「不要出圖」→ 做到步驟 4 的第 1 點，交出 prompt 和選用理由，不呼叫 codex-imagegen。

## 不要做的事

- 不要把上游 skill 的檔案複製、改寫進 `~/.claude/skills/`（會被推上 GitHub，違反部分上游授權）。
- 不要執行 `$V` 裡的 `.app`、Swift、或任何安裝類腳本。
- 不要在商用情境推薦標 ❌ 的風格。
- 不要放官方品牌 logo（J 尤其注意）。

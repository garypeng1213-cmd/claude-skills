# Gary-Style

Gary 的美感系統，分三層，**越上層優先**：

1. **Gary 的偏好**（`my-taste.md`）：疊加在所有成品上的個人習慣。
2. **Gary 的樣板**（`templates/`）：Gary 自己定義的風格，例如中國風、文字風、文字設計。
3. **上游風格**（`styles.md` 的 A～P ＋ `guide.md` 選購指南）：別人寫好的審美 skill，原檔在 `~/.claude/gary-style-vendor/`（下稱 `$V`）。

## 檔案

| 檔案 | 內容 | 什麼時候讀 |
|---|---|---|
| `my-taste.md` | Gary 的美感偏好與偏好紀錄 | **每次都讀** |
| `templates/index.md` | Gary 的樣板索引（分類、標籤、狀態） | **每次都讀** |
| `templates/<分類>/<樣板>.md` | 單一樣板的規則與 prompt 模板 | 選中時才讀 |
| `templates/_template.md` | 新樣板的格式 | 新增樣板時 |
| `styles.md` | 上游風格卡 A～P | 樣板沒有合適的時候 |
| `guide.md` | 選購指南：LEAD/PAIR、15 項完整清單、授權實查表 | 問指南、問授權、需要 LEAD/PAIR 建議時 |
| `setup.sh` | 下載／更新上游到 `$V` | `$V` 缺檔時 |

不要把上游檔案複製進本資料夾：這裡會推上 GitHub，部分上游授權禁止散布。

## 先判斷是哪一種請求

| Gary 說的 | 走哪個流程 |
|---|---|
| 要做一張圖、給素材問適合什麼、點名某個樣板或風格 | **流程一：做圖** |
| 「存成樣板」「幫我做一個 XX 樣板」「改一下 XX 樣板」 | **流程二：建立／修改樣板** |
| 「記住」「以後都要」「我不喜歡」「這張我很喜歡」 | **流程三：記錄偏好** |
| 「指南」「有哪些風格」「這個能商用嗎」 | 讀 `guide.md` 回答，不出圖 |

## 流程一：做圖

### 1. 讀素材，抓五件事

不要一開始就問問題，先推斷：

| 要判斷的 | 怎麼看 |
|---|---|
| **素材類型** | 有照片、只有文字，或兩者都有。有照片就先看內容：主體、場景、光線、色彩、構圖、EXIF 日期。 |
| **照片要不要原樣出現** | 「把這張照片做成…」「保留原圖」→ 保留；「照這張的感覺畫」「當靈感」→ 可以重繪。沒說就預設保留。 |
| **情緒** | 安靜、溫柔、克制、強烈、好笑、理性。從文案用字和照片氣氛判斷。 |
| **用途與比例** | 小紅書 3:4、IG 4:5 或 1:1、限動 9:16、公眾號 21:9、影片封面 16:9、書封 9:16。沒說就用 `my-taste.md` 的常用比例，再沒有就用該風格的預設。 |
| **商用** | 出現「接案、客戶、商品、廣告、要賣、品牌」就視為商用：排除授權標 ❌ 的上游風格，D 要提醒先讀原授權。Gary 自己的樣板不受這個限制，除非樣板是 `based_on` 某個 ❌ 風格。 |

只有完全沒有素材時，才問 Gary 要素材。

### 2. 先找 Gary 的樣板

讀 `templates/index.md`，用需求比對樣板的分類和標籤：

- Gary 點名樣板（例如「用水墨留白」）：直接用。
- 需求明顯屬於某個分類（例如「中國風」「做標題字」）：列出該分類的樣板，優先推薦「定案」的。
- 有合適的樣板：它就是首選，上游風格只當次選。
- **該分類還沒有樣板**：照第 3 步從上游推薦，並在交付時問 Gary 要不要把這次的成果存成新樣板（流程二）。

### 3. 樣板不夠用時，選上游風格

先用下面的決策表縮小範圍，再到 `styles.md` 比對細節。需要搭配建議時，參考 `guide.md` 的 LEAD/PAIR 表。

**只有文字（沒有照片）**

| 想要的感覺 | 首選 | 次選 |
|---|---|---|
| 安靜、留白、金句、文章封面 | A minimal-zine | K mono-color |
| 強烈、有故事、影片／書／專輯封面 | H mondo | I pixel-poster |
| 科技、AI 產品、冷靜 | L kimi-tech | I pixel-poster |
| 文字多、要精準：資訊圖、PPT 配圖、流程圖 | L kimi-tech（資訊圖分支） | — |
| 宣言、活動、編輯排版 | K mono-color | A minimal-zine |
| 超現實、高情緒、滿版 | O dreamcore | G scene-distillation |
| GitHub 開源日報 | M github-daily | L kimi-tech |

**有照片，照片要原樣出現**

| 照片內容／想要的感覺 | 首選 | 次選 |
|---|---|---|
| 家庭、建築、黃昏，要有記憶感、要做成系列 | B photo-relic | C abstract-editorial |
| 構圖漂亮，想要乾淨冷靜的美術館感 | C abstract-editorial | B photo-relic |
| 旅行照，想標日期與地點短句，一地一張 | D travel-abstraction | B photo-relic |
| 風景、植物、街角，想要拼貼手作感 | F gathered-scenes | B photo-relic |
| 飲料、甜點、小物，想要好笑可愛 | J heytea-doodle | E photo-revival |

**有照片，可以重繪（照片只當參考）**

| 想要的感覺 | 首選 | 次選 |
|---|---|---|
| 日記、手帳、溫柔日常 | E photo-revival | A minimal-zine |
| 表達一種情緒，像獨立藝術作品 | G scene-distillation | H mondo |
| 人像特寫、動物，細網點質感 | I pixel-poster | K mono-color |
| 人像或合照做成復古電腦漫畫 | N crt-interface | I pixel-poster |
| 多張照片拼成超現實海報 | O dreamcore | F gathered-scenes |

衝突時的優先順序：商用限制 → 照片要不要保留 → 用途比例 → 情緒。
P eachlabs 不是風格，只在找版型靈感時翻閱，不推薦給 Gary 當選項。

### 4. 推薦給 Gary

給 **2 個**選項（真的只有一個合理時才給 1 個）。每個寫一行理由，加上「成品大概長怎樣」，並標出來源是「你的樣板」還是「上游風格」：

> **推薦 1：你的樣板「水墨留白」** — 這句詩很短，適合大片宣紙留白加一枚朱紅印章。
> **推薦 2：上游 A 極簡 Zine** — 想要更現代、不那麼「中國風」的話選這個。

用 `AskUserQuestion` 讓 Gary 選，推薦的放第一個並標 Recommended。以下情況**不問，直接做首選**：Gary 說「你決定」「直接做」「隨便」，或已經點名樣板或風格。

### 5. 執行

**用 Gary 的樣板時**：讀該樣板檔，照「固定規則」與「Prompt 模板」組 prompt；有參考圖就用 `--ref` 帶入。樣板有寫 `based_on` 上游風格時，也讀那個上游的入口檔補足細節，但以樣板規則為準。

**用上游風格時**：讀 `styles.md` 該卡寫的上游入口 `SKILL.md`，以及它要求讀的 `references/` 檔，照上游規則走（素材判斷、prompt 結構、品質檢查）。`$V` 缺檔就先跑 `bash ~/.claude/skills/gary-style/setup.sh`；clone 失敗（例如雲端網路受限）就改用風格卡的摘要做近似版，並明講不是完整上游規則。

**兩種都要**：

1. 把 `my-taste.md` 的偏好寫進 prompt；跟樣板或風格核心衝突時，以樣板或風格為準，交付時說明。
2. 出圖一律走 codex-imagegen。上游寫「內建生圖工具」「image_gen」「referenced_image_paths」「Wan」「AI Gateway」「each::sense」的地方都改成這個：
   ```bash
   python3 ~/.claude/skills/codex-imagegen/codex_image.py \
     --out "<輸出資料夾>/<檔名>.png" [--ref "<照片或參考圖>"] --prompt-file "<prompt.txt>"
   ```
   比例寫進 prompt，生完必要時用 `sips` 調整。逾時與重試照 codex-imagegen 的說明，在背景執行。
3. 上游的付費 API 腳本不要用。上游的本機處理腳本（例如 D 的 `finalize_artwork.py`）照上游指示，從 `$V` 原位置執行，不複製出來改。
4. 輸出存到 `~/Desktop/Claude skills/gary-style/<YYYY-MM-DD>-<主題>/`，`prompt.txt` 一起存。
5. 生完自己看圖，對照樣板的固定規則或上游的品質檢查；明顯不合格就重生一次。

### 6. 交付

- 用 SendUserFile 送出成品圖，附上路徑。
- 用了哪個樣板或風格、為什麼（一句話）。
- 最終 prompt（上游規定不顯示的照上游，Gary 要求時才給）。
- 跟 `my-taste.md` 有衝突的地方。
- 一個延伸建議：用次選再出一張比較，或「要不要把這次的做法存成樣板？」（該分類沒有樣板時一定要問）。

**只要 prompt**：Gary 說「只要 prompt」「不要出圖」就停在組好 prompt，不呼叫 codex-imagegen。

## 流程二：建立／修改樣板

Gary 可能用這幾種方式給你樣板：

- **從剛做好的成品**：「這張存成樣板」→ 從那次用的 prompt、風格與 Gary 的評語整理。
- **從參考圖**：給一張或多張喜歡的圖 → 逐張看圖，分出「每張都有的固定特徵」「會變的部分」「只屬於某張圖的元素（不要寫進規則）」。只有一張圖時，在樣板裡註明「單張參考，規則待驗證」。
- **從文字描述**：「我要一個宋式極簡的中國風」→ 把描述轉成可畫出來的具體規則（比例、hex 配色、字體氣質、留白比例、質感），模糊的地方問 Gary 一次。
- **從上游風格改**：「用 A 改一個，但要直式中文」→ `based_on: A`，只寫差異。

步驟：

1. 決定分類。現有分類不合適就新增，並更新 `templates/index.md` 的分類表。
2. 照 `templates/_template.md` 的格式寫 `templates/<分類>/<樣板名稱>.md`，`status: 草稿`。
3. 參考圖複製到 `templates/assets/<樣板名稱>/`。只放 Gary 自己的圖或授權清楚的圖；網路上抓的圖只記連結，不存檔。
4. 更新 `templates/index.md` 的樣板清單與分類樣板數。
5. 問 Gary 要不要用這個樣板試做一張。試做後把成品記進樣板的「成品紀錄」，狀態改成「試用中」。Gary 說「定案」才改成「定案」。

修改樣板時，只改 Gary 指定的部分；規則有實質改變時，在成品紀錄加一行說明改了什麼。

## 流程三：記錄偏好

- 「記住」「以後都要…」「我不喜歡…」：寫進 `my-taste.md` 對應段落，並在「偏好紀錄」加一行日期與原話。
- 「這張我很喜歡」：記進 `my-taste.md` 的「已確認喜歡的成品」；如果用的是樣板，也記進該樣板的成品紀錄。
- 只記 Gary 明確說的，不要從單次成品自己推論偏好。
- 新偏好跟舊偏好矛盾時，問 Gary 要保留哪個，不要直接覆蓋。

## 收尾

新增或修改了本資料夾的檔案（樣板、偏好、參考圖），就在 `~/.claude/skills` 只 `git add gary-style` 後 commit 並推送。不要加入其他未追蹤的資料夾。

## 不要做的事

- 不要把上游 skill 的檔案複製、改寫進 `~/.claude/skills/`。
- 不要執行 `$V` 裡的 `.app`、Swift、安裝類腳本，或任何付費 API 腳本。
- 不要在商用情境推薦授權標 ❌ 的上游風格。
- 不要放官方品牌 logo（J、L 尤其注意）。
- 不要把網路上抓來、授權不明的圖存進 `templates/assets/`。
